# 01-構築手順 - プロジェクト作成

## 🎯 目的

NestJS を DevContainer 上に導入し、初期状態で動作する開発環境の構築。  
[公式ドキュメント](https://docs.nestjs.com/first-steps) の「First Steps」を DevContainer 上で再現することが目標。

---

## 🛠️ 構築手順

### 1. DevContainer の設定

本プロジェクトをクローンまたはダウンロードし、**VS Code での起動**。  
※この時点では DevContainer の起動は行わないこと。

#### `.devcontainer/docker-compose.yml` の編集

使用する PC のアーキテクチャに応じた設定の変更：

```yaml
  args:
    - NODE_VER=25
    # 使用環境に応じて 'x86_64' または 'aarch64' を指定
    - ARCH=aarch64
```

---

### 2. DevContainer の起動

設定完了後、VS Code のコマンドパレットから  
**「Reopen in Container」** を選択し、DevContainer の起動。

---

### 3. NestJS プロジェクトの作成

DevContainer 内のターミナルで以下のコマンドを実行：

```bash
nest new sample-project
```

- パッケージマネージャーの選択は `npm`。
- **プロジェクト名は後からの変更が難しいため、慎重な決定が必要。**  
  （変更が必要な場合は、設定ファイル内の名称を `grep` などで一括置換）

---

### 4. プロジェクトのルートディレクトリへの移動

作成された `sample-project` ディレクトリの中身をルートディレクトリへ移動：

```bash
shopt -s dotglob
mv sample-project/* .
shopt -u dotglob
rm -rf sample-project
```

> ※ `.git` ディレクトリの移動は不要。

---

### 5. Node.js / npm のバージョン固定

`volta` を使用した Node.js / npm のバージョン固定：

```bash
volta pin node
volta pin npm
```

---

### 6. VS Code のデバッグ設定

プロジェクトルートに `.vscode` フォルダを作成し、`launch.json` を以下の内容で作成：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Debug Nest Framework",
      "runtimeExecutable": "npm",
      "runtimeArgs": ["run", "start:dev"],
      "cwd": "${workspaceFolder}",
      "sourceMaps": true,
      "console": "integratedTerminal",
      "env": {
        "LOG_TYPE": "console"
      }
    }
  ]
}
```

作成後、VS Code の「実行とデバッグ」から `Debug Nest Framework` を選択し、NestJS アプリの起動を確認。

---

### 7. Git リポジトリの初期化とリモート設定

既存のリモートリポジトリ設定を削除し、新しいリモートリポジトリの登録：

```bash
git remote rename origin old-origin
git remote rm old-origin
git remote add origin <新しいリポジトリURL>
git add .
git commit -m "initial commit"
git push origin master
```

> ※ `main` ブランチを使用している場合は、`master` を `main` に読み替え。

---

## ✅ 補足

- Nest CLI が未インストールの場合は、以下のコマンドによるインストール：

```bash
npm install -g @nestjs/cli
```

- DevContainer の初回ビルドには時間がかかる場合があるため、しばらく待機。
