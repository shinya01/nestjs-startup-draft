# 09-構築手順 - プロトタイプ作成 - レスポンス共通化

## 🎯 目的

NestJS の `Interceptor` を活用し、すべての正常系レスポンスを共通のエンベロープ（包み紙）形式に整形します。これにより、クライアント側は常に同じ構造でデータを受け取ることができ、フロントエンドの実装が簡素化されます。

---

## 🧾 共通レスポンス形式

成功時のレスポンスを以下の構造に統一します。

```json
{
  "success": true,
  "statusCode": 200,
  "timestamp": "2026-01-27T10:00:00Z",
  "path": "/users",
  "data": { ... } // ここに本来のデータが入る
}
```

---

## 🧩 Interceptor の実装

コントローラーが返したデータを `data` フィールドにラップします。

```ts
// src/common/interceptors/response-transform.interceptor.ts
@Injectable()
export class ResponseTransformInterceptor<T> implements NestInterceptor<T, SuccessResponse<T>> {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const ctx = context.switchToHttp();
    const request = ctx.getRequest<Request>();
    const response = ctx.getResponse<Response>();

    return next.handle().pipe(
      map((data) => {
        // 既に meta を含んでいる場合（ページネーション等）と、純粋なデータの場合を判定
        const isPaginated = data && 'meta' in data && 'data' in data;
        
        return {
          success: true,
          statusCode: response.statusCode,
          timestamp: new Date().toISOString(),
          path: request.url,
          ...(isPaginated ? data : { data }),
        };
      }),
    );
  }
}
```

## 🎨 Swagger 用高度なデコレーター

NestJS の Swagger は、ジェネリクス（`SuccessResponse<T>`）の自動認識が弱いため、`getSchemaPath` を用いたカスタムデコレーターを作成して解決します。

### 1. 単一・配列レスポンス用

`@ApiSuccessResponse({ model: UserDto })` のように使用します。

```ts
// src/common/decorators/api-success-response.decorator.ts
export function ApiSuccessResponse<TModel extends Type<any>>(options: ApiSuccessResponseOptions<TModel>) {
  const { model, isArray = false, statusCode = 200 } = options;

  return applyDecorators(
    ApiExtraModels(SuccessResponseDto, model),
    ApiResponse({
      status: statusCode as number,
      schema: {
        allOf: [
          { $ref: getSchemaPath(SuccessResponseDto) },
          {
            properties: {
              data: isArray
                ? { type: 'array', items: { $ref: getSchemaPath(model) } }
                : { $ref: getSchemaPath(model) },
            },
          },
        ],
      },
    }),
  );
}
```

### 2. ページネーション用

`@ApiPaginatedResponse(ArticleDto)` のように使用します。

## 🚀 アプリケーションへの適用 (main.ts)

```ts
// src/main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule, { bufferLogs: true });

  // グローバルインターセプターの登録
  app.useGlobalInterceptors(new ResponseTransformInterceptor());

  // Swagger の extraModels に共通 DTO を登録
  const document = SwaggerModule.createDocument(app, config, {
    extraModels: [SuccessResponseDto, ErrorResponseDto, PaginatedResponseDto],
  });
  // ...
}
```

## 💡 Controller での使用例

```ts
@ApiTags('Users')
@Controller('users')
export class UserController {
  @Get()
  @ApiSuccessResponse({ model: UserDto, isArray: true })
  async findAll() {
    return this.userService.getAll(); // 戻り値は User[] だが、自動でラップされる
  }

  @Post()
  @ApiSuccessResponse({ model: UserDto, statusCode: 201 })
  async create(@Body() dto: CreateUserDto) {
    return this.userService.create(dto);
  }
}
```

## ✅ 補足ポイント

- **204 No Content への配慮**: 削除処理などで `204` を返す場合、`data` フィールドを返さないように Interceptor 内で分岐処理を入れるのが丁寧です。
- **一貫性**: 第8章で作成した `HttpExceptionFilter` とこの `ResponseTransformInterceptor` が組み合わさることで、API の全レスポンス（成功・失敗）が完全に同じメタ情報を持つようになります。
- **開発効率**: フロントエンド側で axios 等のレスポンスインターセプターを作成し、`response.data.data` を常に参照するように設定すれば、通信周りのコードが非常にスッキリします。
