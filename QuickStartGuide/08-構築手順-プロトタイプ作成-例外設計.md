# 08-構築手順 - プロトタイプ作成 - 例外設計と実装

## 🎯 目的

アプリケーション内で発生するエラーを「業務エラー」と「システムエラー」に分類し、  
**2種類の例外クラスで統一的にハンドリング**できるように設計・実装する。  
さらに、業務エラーには **定義済みのエラーコードを付与**し、  
**クライアントに優しい共通構造のレスポンス**を返すことで、開発効率とユーザー体験を向上させる。

---

## 🧩 例外設計の基本方針：2つの分類

| 分類 | クラス名 | 特徴 | レスポンス内容 |
|------|----------|------|----------------|
| 📦 業務エラー | `BusinessException` | 業務ルールに基づく想定内のエラー。独自の `code` を持つ | `success`, `statusCode`, `timestamp`, `path`, `message`, `code` |
| 🛠️ システムエラー | `SystemException` | 想定外の内部エラー。ログ出力対象 | `success`, `statusCode`, `timestamp`, `path`, `message`（codeなし） |

export class BusinessException extends HttpException {
  constructor(
    public readonly code: BusinessErrorCode,
    message: string,
    status: HttpStatus = HttpStatus.BAD_REQUEST,
    public readonly cause?: unknown,

  }
}

## 🧩 共通エラーハンドラーの実装

```ts
// src/common/filters/http-exception.filter.ts
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Request, Response } from 'express';
import { BusinessException } from '../exceptions';

const logger = new Logger('HttpExceptionFilter');

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    const responseBody: Record<string, any> = {
      success: false,
      statusCode: status,
      timestamp: new Date().toISOString(),
      path: request.url,
      message: 'Internal server error',
    };

    if (exception instanceof BusinessException) {
      responseBody.message = exception.message;
      responseBody.code = exception.code;

      logger.warn({
        type: 'BusinessException',
        code: exception.code,
        message: exception.message,
        cause: exception.cause,
        path: request.url,
      });
    } else if (exception instanceof HttpException) {
      const res = exception.getResponse();
      responseBody.message =
        typeof res === 'string' ? res : (res as any).message || 'Error';

      logger.error({
        type: 'HttpException',
        message: responseBody.message,
        path: request.url,
      });
    } else {
      logger.error({
        type: 'UnknownException',
        message: (exception as any)?.message || exception,
        path: request.url,
      });
    }

    response.status(status).json(responseBody);
  }
}
```

## 🛠️ `UserService` の実装（例外設計を反映）

```ts
// src/user/user.service.ts
import { Injectable } from '@nestjs/common';
import { UserRepository } from '../common/repositories';
import { User } from '../common/entities';
import { CreateUserDto } from './dto/create-user.dto';
import { Transactional } from 'typeorm-transactional-cls-hooked';
import { BusinessException } from '../common/exceptions';
import { BusinessErrorCodes } from '../common/constants/business-error-codes';

@Injectable()
export class UserService {
  constructor(private readonly userRepo: UserRepository) {}

  async getAll(): Promise<User[]> {
    return this.userRepo.findAll();
  }

  async getById(id: number): Promise<User> {
    const user = await this.userRepo.findById(id);
    if (!user) {
      throw new BusinessException(
        BusinessErrorCodes.USER_NOT_FOUND,
        `ユーザー（ID: ${id}）が見つかりませんでした`,
      );
    }
    return user;
  }

  @Transactional()
  async create(data: CreateUserDto): Promise<User> {
    const exists = await this.userRepo.findByEmail?.(data.email);
    if (exists) {
      throw new BusinessException(
        BusinessErrorCodes.USER_ALREADY_EXISTS,
        'このメールアドレスは既に登録されています',
      );
    }
    return this.userRepo.save(data);
  }

  @Transactional()
  async remove(id: number): Promise<void> {
    const user = await this.userRepo.findById(id);
    if (!user) {
      throw new BusinessException(
        BusinessErrorCodes.USER_NOT_FOUND,
        `ユーザー（ID: ${id}）が見つかりませんでした`,
      );
    }
    await this.userRepo.delete(id);
  }
}
```

## ✅ 補足ポイント

- `ErrorResponseDto` によって、**Swagger UI 上でも一貫したエラー形式を表示**できる
- `HttpExceptionFilter` によって、**すべての例外が共通構造で返される**
- `cause` はログにのみ出力され、**レスポンスには含まれない**ためセキュア
- `BusinessErrorCodes` によって、**エラーコードの一元管理と型安全性**が実現できる

---

この章では、例外を「業務エラー」と「システムエラー」に分類し、  
それぞれに対応する例外クラスと共通エラーハンドラーを実装し、  
さらにクライアントに優しい共通レスポンス構造と Swagger 定義まで統一した。

これにより、以下のメリットが得られる：

- ✅ クライアント側でのエラー処理が簡潔に
- ✅ フロントエンドとの連携がスムーズに（codeベースで分岐・翻訳可能）
- ✅ ログ出力に cause を含めることで、トラブルシュートが容易に
- ✅ Swagger による API ドキュメントの一貫性が向上
