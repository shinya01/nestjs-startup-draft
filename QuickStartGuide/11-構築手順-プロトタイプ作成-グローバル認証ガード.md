# 11 - グローバル認証ガード構成

> ✅ NestJSアプリケーション全体をデフォルトで保護し、`@Public()` デコレーターで特定のルートのみ認証を免除する「セキュア・バイ・デフォルト」な構成を構築します。

---

## 🧩 構成概要

この構成により、開発者がガードを付け忘れてエンドポイントが露出するリスクを排除します。

- **Global Guard**: すべてのルートに自動で認証を適用。
- **Reflector**: メタデータを読み取り、`@Public()` が付与されたメソッドを特定。
- **Developer Experience**: 開発中は環境変数で認証を完全にバイパス可能。

---

## 🛠️ 実装手順

### 1. `@Public()` デコレーターの作成

メタデータを用いて「このルートは公開されている」という印を定義します。

```ts
// src/auth/decorators/public.decorator.ts
import { SetMetadata } from '@nestjs/common';

export const IS_PUBLIC_KEY = 'isPublic';
export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);
```

---

### 2. ガードの拡張（Reflector の導入）

既存のガードに、公開ルートを判定するロジックを追加します。

```ts
// src/auth/guards/cognito-auth.guard.ts (抜粋)
@Injectable()
export class CognitoAuthGuard extends AuthGuard('cognito') {
  constructor(
    private configService: ConfigService,
    private reflector: Reflector, // メタデータ読み取り用
  ) {
    super();
  }

  canActivate(context: ExecutionContext) {
    // クラス(Controller)またはメソッド(Handler)に @Public() があるか確認
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    // 公開ルートなら検証をスキップして通過
    if (isPublic) {
      return true;
    }

    // 非公開なら親クラス(Passport)の検証ロジックを実行
    return super.canActivate(context);
  }

  handleRequest<TUser = AuthUser>(err: any, user: TUser, info: any): TUser {
    // 開発用バイパスフラグのチェック
    if (this.configService.get<boolean>('app.authDisable')) {
      return { sub: 'dummy-user', iss: 'dummy' } as TUser;
    }

    if (err || !user) {
      throw err || new UnauthorizedException(info?.message || 'Authentication failed');
    }
    return user;
  }
}
```

---

### 3. グローバルガードの適用 (main.ts)

アプリケーション起動時にガードを全ルートへ紐付けます。

```ts
// src/main.ts (抜粋)
async function bootstrap() {
  // ...初期化処理
  const app = await NestFactory.create(AppModule);
  
  const configService = app.get(ConfigService);
  const reflector = app.get(Reflector);

  // 全ルートに認証を適用
  app.useGlobalGuards(new CognitoAuthGuard(configService, reflector));

  // ...Swagger設定など
}
```

---

### 4. Controller での利用例

```ts
@ApiTags('Users')
@Controller('users')
@ApiBearerAuth('access-token')
export class UserController {
  
  @Public() // このメソッドのみ認証なしでアクセス可能
  @Get()
  @ApiOperation({ summary: '全ユーザーを取得（公開）' })
  getAll() {
    return this.userService.getAll();
  }

  @Get(':id') // デフォルトで保護される
  @ApiOperation({ summary: 'IDでユーザーを取得（要認証）' })
  getById(@Param('id') id: number) {
    return this.userService.getById(id);
  }
}
```

---

## ✅ 運用上のメリット

| 機能 | メリット |
| :--- | :--- |
| **デフォルト保護** | 新しい Controller を作成した際、ガードを書き忘れても安全。 |
| **一貫性** | 認証の仕組みが1箇所（ガード）に集約され、メンテナンスが容易。 |
| **明示的公開** | 認証不要な API には `@Public()` が付くため、コードレビューで意図が明確。 |
