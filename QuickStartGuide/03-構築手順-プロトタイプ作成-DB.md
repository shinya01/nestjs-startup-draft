# 03-構築手順-プロトタイプ作成-DB

## 🎯 目的

Docker Compose を使用して PostgreSQL を導入し、NestJS から TypeORM を介してデータベース操作を行える環境を構築します。また、安全な DB 運用のためにマイグレーション管理を導入し、初期データ（Seed）の投入までを行います。

## 🛠️ 構築手順

### 1. PostgreSQL の導入（Docker）

`.devcontainer/docker-compose.yml` を編集し、DB サービスを追加します。

```yaml
version: '3.7'
services:
  nest:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        - NODE_VER=25
        - ARCH=aarch64 # 使用環境に応じて変更
    tty: true
    volumes:
      - ..:/apl
      - ../node_modules:/home/node/app/node_modules
    ports:
      - "3000:3000"

  db:
    image: postgres:17
    restart: always
    environment:
      POSTGRES_USER: devuser
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: myapp
    ports:
      - "5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

設定保存後、VS Code のコマンドパレットから **「Dev Containers: Rebuild Container」** を実行して設定を反映させてください。

### 2. ライブラリのインストール

TypeORM と PostgreSQL ドライバをインストールします。

```bash
npm install --save pg @nestjs/typeorm typeorm
```

### 3. Entity の作成

テーブル定義となる Entity を作成します。

#### `src/common/entities/user.entity.ts`

```ts
import { Entity, PrimaryGeneratedColumn, Column, OneToMany, OneToOne } from 'typeorm';
import { Article } from './article.entity';
import { UserInfo } from './user-info.entity';

@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ unique: true })
  email: string;

  @Column({ unique: true, nullable: true })
  externalId: string;

  @OneToMany(() => Article, (article) => article.author)
  articles: Article[];

  @OneToOne(() => UserInfo, (info) => info.user, {
    eager: true,
  })
  info?: UserInfo;
}
```

#### `src/common/entities/user-info.entity.ts`

```ts
import { Entity, PrimaryGeneratedColumn, Column, OneToOne, JoinColumn } from 'typeorm';
import { User } from './user.entity';

@Entity()
export class UserInfo {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @OneToOne(() => User, (user) => user.info, {
    nullable: false,
    onDelete: 'CASCADE',
  })
  @JoinColumn({ name: 'userId' })
  user: User;
}
```

#### `src/common/entities/article.entity.ts`

```ts
import { Entity, PrimaryGeneratedColumn, Column, ManyToOne, JoinColumn } from 'typeorm';
import { User } from './user.entity';

@Entity()
export class Article {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  title: string;

  @Column()
  content: string;

  @ManyToOne(() => User, (user) => user.articles, {
    nullable: false,
    onDelete: 'CASCADE',
  })
  @JoinColumn({ name: 'authorId' })
  author: User;
}
```

#### `src/common/entities/index.ts`

各 Entity を再エクスポートし、一括インポート用の定数 `ENTITIES` を定義します。

```ts
import { User } from './user.entity';
import { Article } from './article.entity';
import { UserInfo } from './user-info.entity';

export const ENTITIES = [User, Article, UserInfo];
export * from './user.entity';
export * from './user-info.entity';
export * from './article.entity';
```

### 4. AppModule の設定

`TypeOrmModule` を非同期で初期化します。`ENTITIES` 定数を使用して Entity を登録します。

```ts
// src/app.module.ts
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { configuration, validationSchema } from './config';
import { ENTITIES } from './common/entities';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      ignoreEnvFile: true,
      load: [configuration],
      validationSchema,
    }),
    TypeOrmModule.forRootAsync({
      imports: [ConfigModule],
      useFactory: (config: ConfigService) => ({
        type: 'postgres',
        host: config.get<string>('database.host'),
        port: config.get<number>('database.port'),
        username: config.get<string>('database.user'),
        password: config.get<string>('database.pass'),
        database: config.get<string>('database.name'),
        entities: ENTITIES,
        logging: config.get('app.env') !== 'production',
        synchronize: false, // 常にマイグレーションで管理するため false に設定
      }),
      inject: [ConfigService],
    }),
  ],
})
export class AppModule {}
```

> **💡 なぜ `synchronize: false` にするのか？**
> `synchronize: true` にすると、Entity の定義を変更して保存するだけで、TypeORM が自動的に DB のテーブル構造を書き換えます。開発初期は便利ですが、**本番環境でこれを有効にすると、カラムの削除や型変更によって意図せずデータが消失する致命的なリスク**があります。
> 本ハンズオンでは、すべての環境で「どのような変更を加えたか」を履歴（コード）として残せる**マイグレーション方式**に統一するため、この機能を無効化しています。

### 5. マイグレーション実行環境の整備

#### `tsconfig.build.json` の修正

TypeORM CLI（`typeorm-ts-node-commonjs`）がプロジェクトルートにある `data-source.ts` を正しく認識・コンパイルできるよう、`include` に追加します。

> **💡 なぜ `tsconfig.build.json` を修正するのか？**
> デフォルトでは `src` フォルダ内のみがビルド対象となっています。マイグレーション実行時に使用する `data-source.ts` はルートディレクトリに配置するため、ここに明示的に追加しないと、CLI実行時に「ファイルが見つからない」または「TypeScriptとして解釈できない」といったエラーが発生する原因となります。

```json
{
  "extends": "./tsconfig.json",
  "exclude": ["node_modules", "test", "dist", "**/*spec.ts"],
  "include": ["src", "data-source.ts"]
}
```

#### `data-source.ts` の作成（プロジェクトルート）

```ts
import 'dotenv-flow/config';
import { DataSource } from 'typeorm';
import { configuration } from './src/config';

const db = configuration().database;

export default new DataSource({
  type: 'postgres',
  host: db.host,
  port: db.port,
  username: db.user,
  password: db.pass,
  database: db.name,
  entities: [__dirname + '/src/common/entities/*.entity{.ts,.js}'],
  migrations: [__dirname + '/src/migrations/*.ts'],
  synchronize: false,
});
```

#### `package.json` へのスクリプト追加

```json
"scripts": {
  "typeorm": "NODE_ENV=devcontainer typeorm-ts-node-commonjs",
  "migration:generate": "npm run typeorm -- migration:generate src/migrations/AutoGeneratedMigration -d data-source.ts",
  "migration:create": "npm run typeorm -- migration:create src/migrations/SeedData",
  "migration:run": "npm run typeorm -- migration:run -d data-source.ts",
  "migration:revert": "npm run typeorm -- migration:revert -d data-source.ts"
}
```

### 6. マイグレーションの実行とデータ投入

#### テーブルの自動生成

```bash
npm run migration:generate
npm run lint
npm run migration:run
```

#### Seed データ（初期データ）の投入

```bash
npm run migration:create
```

生成された `src/migrations/xxxxxx-SeedData.ts` の `up` メソッドに実装します。

```ts
import { MigrationInterface, QueryRunner } from 'typeorm';

export class SeedData1700000000000 implements MigrationInterface {
  public async up(queryRunner: QueryRunner): Promise<void> {
    const micaUser = (await queryRunner.query(`
      INSERT INTO "user" (email, "externalId")
      VALUES ('mica@fox.jp', NULL)
      RETURNING id
    `)) as { id: number }[];
    const erinUser = (await queryRunner.query(`
      INSERT INTO "user" (email, "externalId")
      VALUES ('erin@forest.jp', NULL)
      RETURNING id
    `)) as { id: number }[];
    const aquaUser = (await queryRunner.query(`
      INSERT INTO "user" (email, "externalId")
      VALUES ('aqua@river.jp', NULL)
      RETURNING id
    `)) as { id: number }[];

    const micaId = micaUser[0].id;
    const erinId = erinUser[0].id;
    const aquaId = aquaUser[0].id;

    await queryRunner.query(`
      INSERT INTO "user_info" (name, "userId")
      VALUES
        ('ミカ', ${micaId}),
        ('エリン', ${erinId}),
        ('アクア', ${aquaId})
    `);

    await queryRunner.query(`
      INSERT INTO "article" (title, content, "authorId")
      VALUES
        ('はじめてのNestJS', 'NestJSはとっても楽しい！', ${micaId}),
        ('PostgreSQL入門', 'データベースの基本を学ぼう！', ${erinId})
    `);
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`DELETE FROM "article"`);
    await queryRunner.query(`DELETE FROM "user_info"`);
    await queryRunner.query(`DELETE FROM "user"`);
  }
}
```

最後に `npm run migration:run` を実行します。
