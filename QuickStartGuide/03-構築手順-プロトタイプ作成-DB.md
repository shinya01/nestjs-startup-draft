# 03-構築手順 - プロトタイプ作成 - DB

## 🐘 PostgreSQL の導入（Docker）

`.devcontainer/docker-compose.yml` に PostgreSQL サービスを追加します。

```yaml
version: '3.8'
services:
  nest:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        - NODE_VER=25
        - ARCH=aarch64 # x86_64 または aarch64
    tty: true
    volumes:
      - ..:/apl
      - ../node_modules:/home/node/app/node_modules
    ports:
      - "3000:3000"
    depends_on:
      - db

  db:
    image: postgres:17
    restart: always
    environment:
      POSTGRES_USER: devuser
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: sample_db
    ports:
      - "5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

## 🧱 Entity の作成（ER図の構築）

共通ディレクトリ `src/common/entities/` に、リレーションを持つ3つのエンティティを作成します。

1. **User**: アカウント基盤
2. **UserInfo**: ユーザー詳細（1対1）
3. **Article**: 記事データ（1対多）

各ファイル作成後、`src/common/entities/index.ts` で一括エクスポートします。

```ts
// src/common/entities/index.ts
import { User } from './user.entity';
import { Article } from './article.entity';
import { UserInfo } from './user-info.entity';

export const ENTITIES = [User, Article, UserInfo];
export { User, Article, UserInfo };
```

## ⚙️ TypeORM の設定（AppModule）

`TypeOrmModule.forRootAsync` を使い、環境変数から接続情報を安全に読み込みます。

```ts
// src/app.module.ts
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { ENTITIES } from './common/entities';

@Module({
  imports: [
    // ... ConfigModule.forRoot 設定（第2章参照）
    TypeOrmModule.forRootAsync({
      imports: [ConfigModule],
      useFactory: (config: ConfigService) => ({
        type: 'postgres',
        host: config.get('database.host'),
        port: config.get('database.port'),
        username: config.get('database.user'),
        password: config.get('database.pass'),
        database: config.get('database.name'),
        entities: ENTITIES,
        logging: config.get('app.env') !== 'production',
        synchronize: false, // 全環境マイグレーション運用を徹底
      }),
      inject: [ConfigService],
    }),
  ],
})
export class AppModule {}
```

## 🛠️ マイグレーション環境の構築

TypeORM CLI が TypeScript ファイルを直接読み込めるように設定します。

### 1. tsconfig.build.json の更新

```json
{
  "extends": "./tsconfig.json",
  "exclude": ["node_modules", "test", "dist", "**/*spec.ts"],
  "include": ["src", "data-source.ts"]
}
```

### 2. data-source.ts の作成（プロジェクトルート）

```ts
// data-source.ts
import 'dotenv-flow/config';
import { DataSource } from 'typeorm';
import configuration from './src/config/configuration';

const db = configuration().database;

export default new DataSource({
  type: 'postgres',
  host: db.host,
  port: db.port,
  username: db.user,
  password: db.pass,
  database: db.name,
  entities: ['src/common/entities/*.entity.ts'],
  migrations: ['src/migrations/*.ts'],
  synchronize: false,
});
```

### 3. package.json へのスクリプト追加

```json
"scripts": {
  "typeorm": "ts-node -r tsconfig-paths/register ./node_modules/typeorm/cli.js",
  "migration:generate": "npm run typeorm -- migration:generate -d data-source.ts src/migrations/AutoGeneratedMigration",
  "migration:run": "npm run typeorm -- migration:run -d data-source.ts",
  "migration:revert": "npm run typeorm -- migration:revert -d data-source.ts",
  "migration:create": "npm run typeorm -- migration:create src/migrations/SeedData"
}
```

## 🌱 マイグレーションの実行とシード投入

### 1. テーブル生成

```bash
npm run migration:generate
npm run migration:run
```

### 2. シードデータの投入（マイグレーション方式）

空のマイグレーションファイルを作成します。

```bash
npm run migration:create
```

生成された `src/migrations/xxxxxx-SeedData.ts` を以下のように実装します。

```ts
import { MigrationInterface, QueryRunner } from 'typeorm';

export class SeedData1700000000000 implements MigrationInterface {
  public async up(queryRunner: QueryRunner): Promise<void> {
    // 1. Userの挿入とIDの取得
    const micaUser = await queryRunner.query(
      `INSERT INTO "user" (email, "externalId") VALUES ('mica@fox.jp', NULL) RETURNING id`
    );
    const erinUser = await queryRunner.query(
      `INSERT INTO "user" (email, "externalId") VALUES ('erin@forest.jp', NULL) RETURNING id`
    );

    const micaId = micaUser[0].id;
    const erinId = erinUser[0].id;

    // 2. UserInfo (1:1) の挿入
    await queryRunner.query(`
      INSERT INTO "user_info" (name, "userId")
      VALUES ('ミカ', ${micaId}), ('エリン', ${erinId})
    `);

    // 3. Article (1:N) の挿入
    await queryRunner.query(`
      INSERT INTO "article" (title, content, "authorId")
      VALUES
        ('はじめてのNestJS', 'NestJSはとっても楽しい！', ${micaId}),
        ('TypeORMの基礎', 'マイグレーションをマスターしよう', ${erinId})
    `);
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`DELETE FROM "article"`);
    await queryRunner.query(`DELETE FROM "user_info"`);
    await queryRunner.query(`DELETE FROM "user"`);
  }
}
```

### 3. シードの適用

```bash
npm run migration:run
```

## ✅ 補足：本番運用を見据えた設計

- **RETURNING id**: IDの不整合を防ぐため、生SQLでも動的にIDを取得。
- **synchronize: false**: アプリ起動時の意図しないスキーマ変更を防止。
- **downメソッド**: ロールバック可能な状態を保つため、削除処理も必ず記述。
