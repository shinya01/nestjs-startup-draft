# 03-構築手順 - プロトタイプ作成 - DB

## 🐘 PostgreSQL の導入（Docker）

`.devcontainer/docker-compose.yml` に PostgreSQL サービスを追加する。  
※ 要件に応じて MySQL などに変更可能。

```yaml
version: '3.7'
services:
  nest:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        - NODE_VER=25
        - ARCH=aarch64 # x86_64 or aarch64
    tty: true
    volumes:
      - ..:/apl
      - ../node_modules:/home/node/app/node_modules
    ports:
      - "3000:3000"

  db:
    image: postgres:15
    restart: always
    environment:
      POSTGRES_USER: devuser
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: myapp
    ports:
      - "5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

> 💡 **PostgreSQL のバージョンは安定版（例：15）を指定するのがおすすめ！**

## ⚙️ TypeORM の設定（AppModule）

```ts
// app.module.ts
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { ConfigModule, ConfigService } from '@nestjs/config';
import configuration from './config/configuration';
import { validationSchema } from './config/validation';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      ignoreEnvFile: true,
      load: [configuration],
      validationSchema,
    }),
    TypeOrmModule.forRootAsync({
      imports: [ConfigModule],
      useFactory: (config: ConfigService) => ({
        type: 'postgres',
        host: config.get('database.host'),
        port: config.get('database.port'),
        username: config.get('database.user'),
        password: config.get('database.pass'),
        database: config.get('database.name'),
        entities: [__dirname + '/common/entities/*.entity{.ts,.js}'],
        synchronize: false, // ← 絶対に true にしない！
      }),
      inject: [ConfigService],
    }),
  ],
})
export class AppModule {}
```

> ⚠️ **`synchronize: true` は使用禁止！**  
> アプリ起動時にテーブルが自動作成・更新されますが、**本番環境で使うと意図せずデータが削除されるリスクがあります。**  
> **すべての環境でマイグレーションを使ってテーブルを管理しましょう。**

## 🧱 Entity の作成

```ts
// src/common/entities/user.entity.ts
import { Entity, PrimaryGeneratedColumn, Column } from 'typeorm';

@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @Column({ unique: true })
  email: string;

  @Column()
  password: string;
}
```

```ts
// src/common/entities/index.ts
import { User } from './user.entity';

export const ENTITIES = [User];
export { User };
```

## 🛠️ マイグレーションの準備

### `tsconfig.build.json` に `data-source.ts` を含める

NestJS のビルド対象に含まれないため、マイグレーションで使用するには明示的に追加する必要がある。

```json
{
  "extends": "./tsconfig.json",
  "exclude": ["node_modules", "test", "dist", "**/*spec.ts"],
  "include": ["src", "data-source.ts"]
}
```

---

### プロジェクト直下に `data-source.ts` を作成

```ts
// data-source.ts
import * as dotenvFlow from 'dotenv-flow';
dotenvFlow.config(); // NestJS と同じ読み込みルール

import { DataSource } from 'typeorm';
import configuration from './src/config/configuration';

const db = configuration().database;

export default new DataSource({
  type: 'postgres',
  host: db.host,
  port: db.port,
  username: db.user,
  password: db.pass,
  database: db.name,
  entities: ['src/common/entities/*.entity{.ts,.js}'],
  migrations: ['src/migrations/*.ts'],
  synchronize: false,
});
```

## 🧩 `package.json` にマイグレーション用スクリプトを追加

```json
"scripts": {
  "migration:generate": "NODE_ENV=devcontainer npx ts-node -r tsconfig-paths/register ./node_modules/typeorm/cli.js migration:generate src/migrations/AutoGeneratedMigration -d data-source.ts",
  "migration:create": "NODE_ENV=devcontainer ts-node -r tsconfig-paths/register ./node_modules/typeorm/cli.js migration:create src/migrations/SeedData",
  "migration:run": "NODE_ENV=devcontainer npx ts-node -r tsconfig-paths/register ./node_modules/typeorm/cli.js migration:run -d data-source.ts",
  "migration:revert": "NODE_ENV=devcontainer npx ts-node -r tsconfig-paths/register ./node_modules/typeorm/cli.js migration:revert -d data-source.ts"
}
```

> 💡 必要に応じて `:development` や `:production` など、環境ごとのスクリプトも追加可能！

## 🧬 マイグレーションの実行手順

### 1. マイグレーションファイルの自動生成

```bash
npm run migration:generate
```

> DB構造の変更を検知してマイグレーションファイルを自動生成。  
> 生成されたファイルは **Git 管理対象に含めること！**

---

### 2. Seed 用マイグレーションファイルの作成

```bash
npm run migration:create
```

`src/migrations/xxxxxx-SeedData.ts` が生成されるので、以下のように実装：

```ts
// src/migrations/xxxxxx-SeedData.ts
import { User } from '../common/entities';
import { MigrationInterface, QueryRunner } from 'typeorm';

export class SeedData1769153762506 implements MigrationInterface {
  public async up(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.manager.insert(User, [
      { name: 'ミカ', email: 'mica@fox.jp', password: 'secret1' },
      { name: 'エリン', email: 'erin@forest.jp', password: 'secret2' },
      { name: 'アクア', email: 'aqua@river.jp', password: 'secret3' },
    ]);
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.manager.delete(User, [
      { email: 'mica@fox.jp' },
      { email: 'erin@forest.jp' },
      { email: 'aqua@river.jp' },
    ]);
  }
}
```

> 🔐 **パスワードは本来ハッシュ化して保存するべきです。ここでは簡略化のためプレーンテキストを使用しています。**
